# API reference

Base URL: `http://localhost:4000` (configurable, see [getting-started](getting-started.md#configuration)).
Format: JSON in, JSON out (`Content-Type: application/json`).

**Access control (optional):** CORS is open unless `CORS_ORIGINS` is set. If `API_TOKEN` is set every `/api/*` call needs `Authorization: Bearer <token>` (`401` otherwise; `/health` is exempt). Send `X-Tstruct-User: <name>` to identify the acting user — it is used as `createdBy`/`modifiedBy` when the body doesn't set one (default `"anonymous"`).

**Struct references:** wherever a path contains `:structRef` / `:structId`, either the struct's **id** (uuid) or its **key** may be used.

## Conventions

* **Ids** are UUID v4 strings generated by the server.
* **Timestamps** are ISO-8601 UTC strings.
* **Errors** are `{ "error": "<message>" }` with an HTTP status. Record validation failures also include `errors`:
  ```json
  { "error": "Validation failed",
    "errors": [ { "fieldId": "days", "message": "Days must be <= 30" } ] }
  ```
* `createdBy` / `modifiedBy` are optional in the body; default: the `X-Tstruct-User` header, else `"anonymous"`.

| Status | Meaning |
|---|---|
| `200` | OK (read / update) |
| `201` | Created |
| `400` | Invalid body (struct definition, key, ref/meta, or record validation) |
| `401` | Missing/wrong bearer token (only when `API_TOKEN` is set) |
| `404` | Struct or record not found |
| `409` | `key` already in use |
| `413` | Uploaded file larger than `MAX_UPLOAD_MB` |
| `500` | Unhandled server error (`{ "error": "Internal server error" }`) |

## Summary

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Liveness check |
| POST | `/api/structs` | Create a struct definition |
| GET | `/api/structs` | List structs (summary) |
| GET | `/api/structs/:structRef` | Full definition (id or key) |
| PUT | `/api/structs/:structRef` | Replace a definition |
| POST | `/api/structs/:structId/records` | Create a record |
| GET | `/api/structs/:structId/records[?ref=…]` | List records of a struct (optionally only those with a `ref`) |
| GET | `/api/structs/:structId/records/:recordId` | One record |
| PUT | `/api/structs/:structId/records/:recordId` | Replace a record's data |
| POST | `/api/options` | Create an option |
| GET | `/api/options` | List options |
| GET | `/api/options/:optionId` | One option |
| PUT | `/api/options/:optionId` | Replace an option |
| DELETE | `/api/options/:optionId` | Delete an option |
| POST | `/api/files` | Upload a file (multipart) |
| GET | `/api/files` | List uploaded files (metadata) |
| GET | `/api/files/:fileId` | Download a file |

## Structs

### Create — `POST /api/structs`

Body:
```json
{
  "name": "Leave Request",
  "key": "leave-request",
  "fields": [
    { "id": "empType", "label": "Employment type", "type": "list", "options": ["Full-time", "Contract"], "required": true },
    { "id": "days", "label": "Days", "type": "wholeNumber", "min": 1, "max": 30, "required": true }
  ],
  "sections": []
}
```
`sections` optional (default `[]`). `key` optional: a stable readable alias (`^[A-Za-z][A-Za-z0-9_-]{0,63}$`, unique, not UUID-like) usable instead of the id in every path. Field/section/condition schema: [field-types-and-conditions.md](field-types-and-conditions.md).

`201`:
```json
{ "structId": "5b0c…", "struct": { "id": "5b0c…", "name": "Leave Request", "fields": [ … ], "sections": [],
  "createdBy": "anonymous", "createdAt": "2026-09-24T15:16:27.593Z" } }
```
`400` when: `name` missing/blank, `fields` not a non-empty array, a field lacks `id`/`label`/valid `type`, two fields share an `id`, or `key` is malformed. `409` when `key` is already used.

```bash
curl -X POST localhost:4000/api/structs -H 'content-type: application/json' \
  -d '{"name":"Demo","fields":[{"id":"a","label":"A","type":"text","required":true}]}'
```

### List — `GET /api/structs`

`200`, newest first:
```json
{ "structs": [
  { "id": "5b0c…", "key": "leave-request", "name": "Leave Request", "createdAt": "…", "modifiedAt": "…",
    "fieldCount": 14, "sectionCount": 1, "recordCount": 4 } ] }
```
`key` and `modifiedAt` are present only when set / after an edit.

### Get — `GET /api/structs/:structRef`

`200 { "struct": { …full definition… } }` · `404 { "error": "Struct not found" }`

### Update — `PUT /api/structs/:structRef`

Body: same as create (`name`, `fields`, `sections`, optional `modifiedBy`). `key`: omit to keep the current one, a string to set/change it, `null`/`""` to remove it (`409` if taken). Replaces the definition; `id`, `createdBy`, `createdAt` are kept and `modifiedBy`/`modifiedAt` are set. Existing records are **not** migrated.

`200 { "structId": "…", "struct": { … } }` · `400` (same rules as create) · `404`.

Tip: keep the `id` of every existing field unchanged so saved records stay valid (the UI does this automatically).

## Records

### Create — `POST /api/structs/:structId/records`

Body:
```json
{ "data": { "empType": "Full-time", "days": 12 },
  "ref": "order-42",
  "meta": { "source": "crm" } }
```
`ref` (string ≤ 200 chars) and `meta` (JSON object) are optional host-linking fields, returned on the record.
The server validates `data` against the struct (see [backend.md → Validation](backend.md#validation-rules)); fields hidden by a false condition are not validated.

`201`:
```json
{ "recordId": "0d7e…", "record": { "id": "0d7e…", "structId": "5b0c…", "data": { … },
  "createdBy": "anonymous", "createdAt": "…", "modifiedBy": "anonymous", "modifiedAt": "…" } }
```
`400` validation failure (see error format above) or invalid `ref`/`meta` · `404 { "error": "Struct not found" }`.

### List — `GET /api/structs/:structId/records`

`200 { "records": [ … ] }` newest first. With `?ref=order-42` only records whose `ref` equals it are returned. An unknown struct returns an empty list (`[]`) rather than 404.

### Get — `GET /api/structs/:structId/records/:recordId`

`200 { "record": { … } }` · `404 { "error": "Record not found" }`

### Update — `PUT /api/structs/:structId/records/:recordId`

Body: `{ "data": { … }, "modifiedBy": "optional", "ref": …, "meta": … }`. `ref` / `meta`: omit to keep, send a value to replace, `null` to remove. `data` **replaces** the stored data (send every visible field, not a patch). Validated like create. `id`, `structId`, `createdBy`, `createdAt` are kept; `modifiedBy`/`modifiedAt` are updated.

`200 { "recordId": "…", "record": { … } }` · `400` validation failure · `404 { "error": "Struct not found" }` or `404 { "error": "Record not found" }`.

```bash
curl -X PUT localhost:4000/api/structs/$SID/records/$RID -H 'content-type: application/json' \
  -d '{"data":{"a":"changed"}}'
```

## Options

An **Option** is a standalone configurable action (not tied to a struct). Guide: [options.md](options.md).

```json
{ "id": "…", "caption": "Apply for leave", "type": "dataInput", "config": { "structName": "Leave Request" },
  "applicableTo": { "userCategories": { "scope": "all", "selected": [] }, "affiliate": { … }, "employee": { … } },
  "createdBy": "anonymous", "createdAt": "…", "modifiedBy": "…", "modifiedAt": "…" }
```

| `type` | `config` | Validation |
|---|---|---|
| `dataInput` | `{ structName }` | non-empty string (the struct is only looked up when the option is run) |
| `download` | `{ fileId }` | the file must exist (`POST /api/files` first) |
| `upload` | `{}` | — |
| `apiDisplay` | `{ apiName, displayAs }` | `displayAs` ∈ `table`, `nameValuePair`, `text` |
| `pay` | `{ paymentConfig }` | string |
| `axpertOption` | `{ subtype, target }` | `subtype` ∈ `tstruct`, `smartView`, `iview`, `customPage` |

`applicableTo` (optional, stored but **never enforced** — no user identity yet; see [options.md](options.md#applicable-to)):
`{ userCategories: { scope: 'all'|'selected', selected: [...] }, affiliate?: { affiliates: Scope }, employee?: { departments, branches, designations: Scope } }` with `Scope = { scope: 'all'|'selected', selected: string[] }`. The `affiliate` / `employee` blocks are kept only when the (effective) categories contain that category — the same show/hide condition mechanism as struct sections; irrelevant blocks are dropped, missing ones get `{ scope: 'all' }` defaults, category names are lower-cased. Selected scopes need at least one value.

### Create — `POST /api/options`
Body `{ caption, type, config, applicableTo? }`. `201 { optionId, option }` (normalised). `400` on a missing caption, unknown type, invalid config (see table) or invalid `applicableTo`.

```bash
curl -X POST localhost:4000/api/options -H 'content-type: application/json' \
  -d '{"caption":"Apply for leave","type":"dataInput","config":{"structName":"Leave Request"}}'
```

### List — `GET /api/options`
`200 { "options": [ … ] }`, newest first.

### Get — `GET /api/options/:optionId`
`200 { "option": {…} }` · `404 { "error": "Option not found" }`

### Update — `PUT /api/options/:optionId`
Same body as create; replaces caption/type/config/applicableTo. `id`, `createdBy`, `createdAt` are kept; `modifiedBy`/`modifiedAt` set. `200 { optionId, option }` · `400` · `404`.

### Delete — `DELETE /api/options/:optionId`
`200 { optionId, deleted: true }` · `404`. A file the option referenced is **not** deleted.

## Files

Uploaded files are stored on the API server's disk (`server/uploads/`); metadata in Redis. See [options.md](options.md#file-storage).

### Upload — `POST /api/files`
`multipart/form-data` with one field named `file`. `201`:
```json
{ "fileId": "c3a7…", "file": { "id": "c3a7…", "originalName": "policy.pdf", "mimeType": "application/pdf", "size": 300000,
  "uploadedAt": "…", "uploadedBy": "anonymous" } }
```
`400 { error }` when no file is sent · `413` when larger than `MAX_UPLOAD_MB` (default 25). UTF-8 file names are preserved. The server-side path is never returned.

```bash
curl -X POST localhost:4000/api/files -F "file=@policy.pdf"
```

### List — `GET /api/files`
`200 { "files": [ …metadata… ] }`, newest first (used to pick a previously uploaded file).

### Download — `GET /api/files/:fileId`
Streams the file with `Content-Disposition: attachment; filename="…"; filename*=UTF-8''…`, the stored `Content-Type`, `Content-Length` and `X-Content-Type-Options: nosniff`. `404 { "error": "File not found" }`. `Content-Disposition` is exposed to cross-origin browser code (CORS `exposedHeaders`).

```bash
curl -OJ localhost:4000/api/files/<fileId>      # saves it under its original name
```

## Data conventions for `record.data`

| Field type | Stored as |
|---|---|
| `text` | string (multi-line keeps `\n`) |
| `wholeNumber`, `number` | JSON number |
| `date` | `"YYYY-MM-DD"` |
| `time` | `"HH:MM"` |
| `email`, `url` | string |
| `mobile` | E.164 string, e.g. `"+919876543210"` |
| `location` | `{ "lat": 12.9716, "lng": 77.5946 }` |
| `list` | one of `options` |
| `selection` | the chosen item's value (string) |
| `fill` | the derived string (saved for convenience) |

## External API used by `selection` fields

A `selection` field's `apiUrl` is fetched **from the browser** at form time (`GET`, no auth). It must allow CORS and return JSON: an array, or an object with `items`, `data` or `results` holding the array. Each entry is a string or an object:

```json
[ { "id": "v1", "name": "Acme", "email": "acme@x.com" }, "Plain string option" ]
```
* value = `id ?? value ?? name ?? label ?? title`; label = `label ?? name ?? title ?? id ?? value`.
* A `fill` field with `sourceField` pointing at the selection field shows `item[sourceProp]` (or the item's label when `sourceProp` is empty).
